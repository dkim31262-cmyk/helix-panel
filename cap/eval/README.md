# HELIX CAP versus Work — Observed Experiment, not a parity claim

Study hypothesis: CAP can improve accepted outcomes for some tasks. No universal parity can be inferred. Use observable authorized Work artifacts, not fake simulations or hidden reasoning.

## Controlled versus Naturalistic conditions
**Controlled quality:** same task, predeclared rubric, source snapshot and matched tool permissions where feasible. Report any entitlement mismatch.
**Naturalistic product:** real Chat/CAP/Work availability, browser ability and background execution differences; these affect interpretation.

Preregister before running outputs. Pilot **12** tasks (two across each of six classes) calibrates criteria. Confirmatory **48** tasks (eight per class) remains exploratory for per-class parity; more tasks and power analysis needed for strong equivalence. Two independent **blind** evaluators rate each output 0–5. Keep complete output references and failures.

Call normalizeStudy with registration, runs and ratings, then scoreStudy. Report uncertainty (paired bootstrap 95% intervals), acceptance rate, blind quality, critical failures, time, interventions, cost and tool count. Missing Work runs are missing, not zero; absence of price data is unknown, not free. A practical preliminary screen needs no critical errors, CAP median quality gap no more than 0.5/5 and acceptance gap no more than 10pp.

## Baseline and ablation
Compare plain Chat baseline, Chat+CAP and Work on held-out tasks. Record ablation of Tool Instinct, Evidence Verification, Adaptive Routing and Checkpoints separately. Do not replace missing Work with baseline. No actual Work data is generated by this documentation.
